# 微信支付平台证书切换公钥

适用商户号：`1609112136`。官方指引：[如何从平台证书切换成微信支付公钥](https://pay.weixin.qq.com/doc/v3/merchant/4012154180)。

## 第二步：开发与部署配置

支付入口由 `api/modules/v1/components/Wechat.php` 统一创建 `WechatPayApplication`，v1/v2 的下单、查单、退款、支付通知与退款通知均使用该组件。

- 每次请求默认携带 `Wechatpay-Serial: <WECHAT_PUB_KEY_ID>`，同一客户端连续请求也保留该头。
- APIv3 成功应答在读取业务 JSON 前验证原始响应签名，支持 `204` 空响应。HTTP 错误、缺失签名、未知 serial 和签名不匹配均抛出异常，不作为成功支付结果。
- 回调在解密通知和调用业务处理器之前验证原始请求签名。
- 验签由 SDK 按响应/回调的 `Wechatpay-Serial` 精确选取配置的公钥或平台证书，不回退尝试其他密钥。

现有商户私钥、商户 API 证书和 APIv3 密钥继续使用原配置。新公钥只用于验证微信身份，不能替换商户私钥或商户 API 证书。

用户下载的两份文件内容相同，已确认均为有效 RSA 公钥：

```text
公钥 ID：PUB_KEY_ID_0116091121362025052600392095001000
文件：PUB_KEY_ID_0116091121362025052600392095001000.pem / pub_key.pem
SHA256：cbbce05c8f4e9ce607c7c5ab67ed372fb4ef625600c1d1c5a0c638ce6c4b3b08
```

将新公钥放入现有密钥挂载目录，下面使用新的文件名示例，避免覆盖旧平台证书。容器环境变量示例：

```dotenv
WECHAT_MCH_ID=1609112136
WECHAT_PUB_KEY_ID=PUB_KEY_ID_0116091121362025052600392095001000
WECHAT_PUB_KEY=/var/www/.ssh/wechatpay-public-key.pem
WECHAT_PLATFORM_CERTS=["/var/www/.ssh/wechatpay-platform-old.pem"]
```

上面的两个文件路径是部署示例，必须替换成实际容器中可读取的挂载路径。`WECHAT_PLATFORM_CERTS` 为 JSON 字符串路径列表，包含全部仍可能用于签名的有效平台证书。代码从每张 X509 证书中读取其真实序列号；通知中的旧证书序列号为 `49ECC9F552F696CC0CE79EB6B5548D34D6E77AB6`，需核对现有证书。

如尚未迁移某个实例，旧的 `WECHAT_PUB_KEY_ID=<平台证书序列号>`、`WECHAT_PUB_KEY=<平台证书路径>` 仍受支持，未设置 `WECHAT_PLATFORM_CERTS` 时默认为空列表。但要切换公钥灰度，必须实际配置新公钥并保留旧平台证书。

部署前，逐个核对 B0、B1、旧 `x.4mr.cn` 和所有复用此商户号的其他系统。先保留旧文件、放好新公钥，再配置两种验签材料并发布兼容代码；逐实例检查与观察回调日志，避免先覆盖证书文件再补代码造成失败。不要在过渡期移除旧证书。

离线测试：

```sh
php api/vendor/bin/phpunit --do-not-cache-result --bootstrap api/tests/_bootstrap.php api/tests/unit/components/WechatPayVerificationTest.php
```

测试使用独立生成的测试 RSA 密钥、测试 X509 证书、AES-GCM 回调和模拟 HTTP。不会创建真实订单、付款或退款。离线通过不等于线上真实支付已验收。

## 第三步：更换验签方式与验收

用户提供的商户平台截图已显示“正在从平台证书切换为公钥 / 切换中”，说明流程已启动。需要查看进度页面进一步确认两项实际比例。

1. 确认所有使用该商户号的系统都已部署兼容代码和正确的新旧验签材料。
2. 在商户平台“微信支付公钥 → 查看进度”查看回调与应答比例，记录开始时间。
3. 回调公钥比例由微信平台在约 7 天内逐步提升，灰度期间同时支持两种签名。
4. 应答公钥比例由商户请求中的 `Wechatpay-Serial` 决定。平台展示近 7 天的调用统计，约每小时更新；全部请求开始使用公钥后，展示比例仍可能需要时间达到 100%。不能通过反复测试下单或刷请求来伪造进度。
5. 观察真实下单、查单、支付通知、退款及退款通知的验签结果。未知 serial 或验签失败应排查遗漏实例、错误文件或错误配置，不关闭验签。
6. 回调和应答均为 100%、全部业务覆盖且运行稳定后，由商户管理员在平台点击“确认切换”。旧平台证书的移除安排在确认切换和业务复核之后。

本次浏览器自动化访问微信商户平台已被站点安全策略阻止，不能用其他浏览器或接口绕过。平台进度与最终确认由用户在自己的页面操作。用户已在内置浏览器登录 B0/B1 Portainer，后续部署结果另记；尚未进行真实支付验收。
